## Fix 1: Невидима DR следа (`isContinous = true`)

### Проблем

Потребителят съобщи, че при изключен GPS и включен tracking, следата
(линията) **изчезва от картата**, въпреки че навигацията по DR точките
продължава. При повторно включване на GPS следата се появява отново,
но с **прекъсване** — липсва линия в GPS-off периода.

### Root Cause

В `LocationService.kt` (~ред 1450), DR dispatch-ът задаваше:

```kotlin
isContinous = false   // ← БЪГ
```

Това кара `TrackOverlay.onDraw()` да използва `path.moveTo(x, y)` вместо
`path.lineTo(x, y)`. `moveTo()` само мести "химикала" без да чертае линия.
Резултат: точките се записват в SQLite ✅, но визуално линията е невидима.

### Fix

```kotlin
isContinous = true    // ← DR е непрекъснато физическо движение
```

Time/distance филтърът в `writeTrack()` продължава да работи, ограничавайки
реалните DB записи до ~2/сек (както при GPS tracking).

### Файлове
- `borkozic/src/main/java/com/borkozic/location/LocationService.kt`
- `borkozic/src/main/java/com/borkozic/overlay/TrackOverlay.kt` (анализиран)

## Fix 4: Адаптивен bias noise + понижен праг

### Проблем

Във всички DR логове `biasN=0.0000, biasE=0.0000` — дори след 40-50 секунди
чисто инерциална навигация. Причина:

1. `HIGH_ACCEL_THRESHOLD = 1.0 m/s²` (~0.1g) — твърде висок за нормално
   градско каране. В реални тестове earthAccel magnitude = 0.39–0.85 m/s².
2. `BIAS_NOISE_DENSITY = 0.001` беше **константа** — никога не се променяше
   независимо от ускорението. Без достатъчен process noise, bias covariance
   матрицата не расте, и Kаlman gain-ът за bias остава ~0.

### Fix

**Threshold:** `1.0` → `0.5 m/s²` (~0.05g) — задейства се дори при леко каране.

**Bias noise става адаптивен:**

| Режим | Условие | Bias noise | Qb в лога |
|---|---|---|---|
| Cruise | earthAccel < 0.5 m/s² | `BIAS_NOISE_DENSITY_CRUISE = 0.001` | `Qb=0.001` |
| Maneuver | earthAccel ≥ 0.5 m/s² | `BIAS_NOISE_DENSITY_MANEUVER = 0.05` | `Qb=0.050` |

При маневра — 50× по-висок process noise за bias states, което позволява
на Kаlman gain-а да коригира bias при следващ GPS fix.

### Важно уточнение

**Bias не може да се промени без GPS measurement update.** Kalman predict
стъпката само разширява ковариацията (P[4][4], P[5][5]), но не променя
самите bias стойности (x[4], x[5]). Bias се коригира ЕДИНСТВЕНО чрез
GPS update-а — когато velocity innovation-ът покаже систематична грешка.
Затова `biasN/biasE = 0.0000` в pure DR режим (без GPS) е **очаквано
поведение** — филтърът правилно не мърда bias без външна корекция.

Целта на адаптивния Qb е да **подготви** bias covariance-а (P матрицата)
за по-агресивна корекция при **следващ** GPS fix — когато GPS се върне,
Kalman gain-ът за bias ще е по-висок и bias-ът ще се коригира по-бързо.

### Файлове
- `borkozic/src/main/java/com/borkozic/location/DeadReckoningKalman.kt`
  - `HIGH_ACCEL_THRESHOLD`: 1.0 → 0.5
  - `BIAS_NOISE_DENSITY` (константа) → `BIAS_NOISE_DENSITY_CRUISE` + `BIAS_NOISE_DENSITY_MANEUVER` (адаптивен)
  - `lastBiasDensity`: нова debug променлива
  - `getDebugState()`: добавен `Qb=%.3f` в лога

## 1. Language Switching — Locale Crash

**Commits:** `e8ac882`, `e53fcbf`, `34bcd3f`

### Проблем
`applyOverrideConfiguration()` в `onCreate()` crash-ваше с `IllegalStateException: getResources() has already been called`. Android зарежда resources преди `onCreate()` да се изпълни, така че е невъзможно да се вика там.

### Решение
Locale-ът се прилага в `attachBaseContext()` на всяка Activity — единственото правилно място:

```kotlin
// BaseApplication.kt — чете locale веднъж и го пази статично
override fun attachBaseContext(base: Context?) {
    val lang = PreferenceManager.getDefaultSharedPreferences(base!!).getString("locale", "") ?: ""
    if (lang.isNotEmpty()) {
        val locale = Locale(lang)
        Locale.setDefault(locale)
        savedLocale = locale  // static field — достъпен от Activity без resource access
        val config = Configuration(base.resources.configuration)
        config.setLocale(locale)
        super.attachBaseContext(base.createConfigurationContext(config))
        return
    }
    savedLocale = null
    super.attachBaseContext(base)
}

// MapActivity.kt / Preferences.kt — прилагат locale от static field
override fun attachBaseContext(newBase: Context) {
    val locale = BaseApplication.savedLocale
    if (locale != null) {
        val config = Configuration(newBase.resources.configuration)
        config.setLocale(locale)
        super.attachBaseContext(newBase.createConfigurationContext(config))
    } else {
        super.attachBaseContext(newBase)
    }
}
```

Рестартът е чрез `recreate()` — `killProcess()` е лошо UX и ненужно.

## 3. NavigationService Foreground Crash

**Commits:** `450bf29`, `1369db8`, `92d75a8`, `732e0de`, `e93868a`, `6826e26`, `0e26cfb`, `72ccc27`

### Проблем
`CannotPostForegroundServiceNotificationException: Bad notification for startForeground` на Samsung Android 14.

### Root Cause (след множество итерации)
Samsung Android 14 изисква **всички** от следните условия:

| Изискване | Причина |
|---|---|
| `IMPORTANCE_LOW` (не `IMPORTANCE_NONE`) | Android 14 отказва silent channels за foreground |
| Валиден `contentIntent` | Задължителен PendingIntent |
| `Notification.Builder(ctx, channelId)` (**не** `NotificationCompat`) | `NotificationCompat` има бъг — не сетва `mChannelId` на API 34+ |
| `setOngoing(true)` | Samsung изисква за foreground notifications |
| `setChannelId(CHANNEL_ID)` експлицитно | Samsung понякога губи channel от конструктора |
| `FLAG_FOREGROUND_SERVICE` флаг | Задължителен на Android 14+ |
| Rebuild при всяко `startForeground()` | Stale обекти губят channel reference |

### Архитектура
```
onCreate()
  ├─ createNotificationChannel()   // само channel-ът
  └─ contentIntent = fallback PendingIntent(MapActivity)

ensureForeground()                 // вика се само когато !isForeground
  ├─ check ACCESS_FINE_LOCATION
  ├─ REBUILD notification (fresh всеки път)
  ├─ startForeground(TYPE_LOCATION на API 34+)
  └─ isForeground = true

navigateTo(waypoint/route)
  ├─ clearNavigation()
  ├─ connect()
  └─ if (!isForeground) ensureForeground()   // само при първо стартиране

stopNavigation()
  ├─ stopForeground(true)
  └─ isForeground = false
```

```kotlin
// Force movinginfo VISIBLE при навигация (независимо от движение)
if (isNavigating) {

// Restore нормалното поведение при спиране
if (!isNavigating) {
    updateGPSStatus()
}
```

## 5. Navigation Line Not Drawing on Target Switch

**Commit:** `92d75a8`

### Проблем
При смяна route→waypoint, `NavigationOverlay` вече съществуваше → `if (overlay == null)` беше false → `onMapChanged()` не се викаше → линията не се рисуваше.

### Решение
`onMapChanged()` се вика винаги при смяна на навигационно состояние:
```kotlin
if (isNavigating) {
    if (application!!.navigationOverlay == null) {
        application!!.navigationOverlay = NavigationOverlay(this)
    }
    application!!.navigationOverlay!!.onMapChanged()  // Always refresh
}
```

## Key Technical Lessons

1. **`applyOverrideConfiguration()` CANNOT be in `onCreate()`** — use `attachBaseContext()` instead
2. **`NotificationCompat.Builder` is broken on Android 14** — use `Notification.Builder(ctx, channelId)`
3. **Samsung Android 14 foreground service** needs: `IMPORTANCE_LOW` + valid contentIntent + `setOngoing(true)` + `setChannelId()` + `FLAG_FOREGROUND_SERVICE`
4. **`startForeground()` must not be called twice** — use `isForeground` flag
5. **`setRouteWaypoint()` requires active navRoute** — for waypoint navigation use `navigateTo(wpt)`
6. **`NotificationCompat` channel bug** — `mChannelId` not set properly → `channel=null` in logs → crash
